01 / 待ち行列理論とは？

人や仕事が到着し、順番を待ち、窓口で処理される仕組みを数学で扱うものです。

「レジ」「ATM」「もぎり」の数学、とも言えましょう。

このシミュレーターでは、その数学をわかりやすく学べます。

02 / 利用率ρ（ロー）とは？

「客」とは、窓口での対応を受ける人です。レジの買い物客、ATMの利用者、もぎりを通る来場者などが当てはまります。

「窓口数」は、1人ずつ順番に対応する受付・レジ・入場レーンなどの数です。同時に4人に対応できる独立したレーンがあれば、4窓口と数えます。

「サービス時間」は、窓口での対応にかかる時間です。列に並んでいる待ち時間は含みません。

「サービス数」は、1窓口が1時間あたりに対応できる平均人数です。たとえばサービス時間が平均2分なら、サービス数は60 ÷ 2 = 30人/時です。

1/λ = 平均到着間隔、1/μ = 平均サービス時間です。λ・μを「人/時」で表すと、逆数の単位は「時間」になります。分で表すなら、平均到着間隔は60/λ、平均サービス時間は60/μです。

たとえばλ = 90人/時なら平均到着間隔は約0.67分（40秒）、μ = 30人/時なら平均サービス時間は2分です。λ = 0のときは客が到着しないため、平均到着間隔は∞として扱います。

たとえば、

  • 窓口数 c = 4
  • 到着数 λ（ラムダ）= 90（人/時）：1時間あたりに到着する平均人数
  • サービス数 μ（ミュー）= 30（人/時）：1窓口が1時間あたりに対応できる平均人数
  • 合計処理能力 = c × μ = 4 × 30 = 120（人/時）

利用率ρ（ロー）とは、合計処理能力をどれくらい使い切っているかを示す数字です。到着数を合計処理能力で割って求めます。

ρ = λ ÷ (c × μ) = 90 ÷ 120 = 0.75（75%）

この例では、合計処理能力の75%に相当する客が到着しています。ρ > 1は到着数が合計処理能力を超えているという意味で、実際の稼働割合が100%を超えるわけではありません。

窓口数c・到着数λ・サービス数μを動かしてみる

利用率ρ（ロー）0.75（75%）90 ÷ (4 × 30) = 0.75

処理能力に余裕があります。

03 / ρが1に近づくと、急激に待ち時間が悪化する

ρが増えれば増えるほど、平均待ち時間が悪化します。
特にρが0.9〜1に近づくにつれて、待ち時間は急激に悪化します。

  • 窓口が1個減っただけで急に悪化する。
  • サービス時間が少し長くなっただけで急に悪化する。

下は1窓口・平均サービス時間1分の定常理論値です。到着間隔・サービス時間のばらつきはランダムです（専門的には「ポアソン到着・指数サービス」といい、窓口が1つの場合を「M/M/1」と呼びます）。サービス中の時間を含まない、行列での平均待ち時間を示します。

Wq = ρ ÷ (1 − ρ) × 平均サービス時間
この式は 0 ≤ ρ < 1 で使います。

04 / 1を超え続けると、待ち時間は発散する

ρが1を超えると、行列の長さは∞に発散し、待ち時間も∞に発散します。
この状態では待ち時間はどんどん長くなっていきます。

ρ = 1 も安心ではありません。このアプリの M/M/c モデルでは、ばらつきによる行列を吸収する余裕がなく、有限の定常平均待ち時間は得られません。安定条件は ρ < 1 です。

到着120人/時、1窓口の処理能力100人/時（ρ = 1.20）。左から到着し、列に並び、窓口で処理されて右へ退出します。

時間が経つにつれて行列がどんどん長くなります。

スライダーを動かすと、その時点へ移動して一時停止します。

基本タブと同じM/M/1モデルと描画です。1人ずつの待ち時間・窓口の残り時間を表示します。到着と処理にばらつきがあるため、列は一時的に短くなることもあります。1秒で1分進み、60分で停止します。リセットすると同じ乱数シードで再開します。

05 / ばらつきが大きくても、ρが小さければ待ち時間は収束する

客が集中すると、一時的に窓口でさばききれず、待ち時間が発生します。
しかしρの値が1よりも十分に小さければ、そのばらつきを受け止めて、平均待ち時間を小さくできます。

ここでは到着のばらつきだけを変えてみましょう。
平均到着数45人/時、1窓口のサービス数60人/時、ρ = 0.75は同じです。

0：一定間隔 ／ 1：ランダム（ポアソン到着）／ 2：到着がまとまりやすい

ばらつきを大きくすると、しばらく誰も来ない時間と、客がまとまって来る時間が現れます。

スライダーを動かすと、その時点へ移動して一時停止します。

基本タブと同じモデル・描画です。サービス時間は平均1分の指数分布。1秒で1分進み、60分で停止します。ばらつきの変更・リセット時は同じ乱数シードで最初から計算します。60分の実測値には偶然の差があり、設定間の実際の到着人数も異なります。表示する平均待ち時間は、窓口で対応を開始した客の平均です。

06 / 目標利用率は、まず60〜80%から考える

経験的には、ρ = 0.6〜0.8 程度がほどよい目安です。
（※普遍的な基準はありません、到着時間・対応時間のばらつきが大きい場合にはρ=0.5もよいでしょう）

同じ客が来ても、窓口数が1つ変動するだけでρが大きく変わってしまうことがあります。
到着90人/時・1窓口30人/時を共通にして、同時に比較します。

スライダーを動かすと、その時点へ移動して一時停止します。

3窓口 ρ = 1.00：安定条件を満たさない

4窓口 ρ = 0.75：能力に余裕

3窓口ではばらつきを吸収する余裕がありません。4窓口では余力で行列を解消できます。短い時間では列が増減するため、常に一方の列が長いとは限りません。

基本タブと同じモデル・描画。両方に同じ到着時刻と、客の順番ごとに同じサービス時間を与えます。到着はポアソン過程、サービス時間は平均2分の指数分布です。1秒で1分進み、60分で停止します。リセットすると同じ条件を再現します。平均待ち時間は対応開始済みの客についての実測値で、有限時間の結果です。

窓口を増やすほど待ち時間は減りますが、追加費用もかかります。仮に1窓口2,000円/時なら、3窓口は6,000円/時、4窓口は8,000円/時です。さらに増やすべきかは、待ち時間短縮の価値と追加費用、サービス目標で判断します。

07 / 窓口の前・窓口の後にボトルネックを作らない

入口・事前確認
60人/時→窓口
120人/時→受け取り・出口
50人/時

全員がこの順で通るなら、全体の持続的な処理能力は最大でも50人/時です。窓口に余裕があっても、入口で待たされたり、出口で詰まったりします。出口の滞留が窓口をふさぐこともあります。

窓口のρだけを目標にするのではなく、入口・案内・受付・受け取り・通路・出口の待ち人数と能力を確認しましょう。「行列ボトルネック」では通路の狭さや遅い歩行者による滞留を観察できます。窓口との連結モデルではなく、通路単体の例です。

どちらも到着90人/時、主窓口は4窓口 × 30人/時 = 120人/時です。窓口の前と後の処理能力だけを変えて比べます。

窓口の前で詰まる：事前確認が60人/時

上から順に、事前確認 → 主窓口 → 受け取りを通ります。同じ客が前の工程を終えて次へ進みます。

① 事前確認（窓口の前）：合計60人/時

② 主窓口：合計120人/時

③ 受け取り（窓口の後）：合計120人/時

窓口の後で詰まる：受け取りが50人/時

上から順に、事前確認 → 主窓口 → 受け取りを通ります。同じ客が前の工程を終えて次へ進みます。

① 事前確認（窓口の前）：合計120人/時

② 主窓口：合計120人/時

③ 受け取り（窓口の後）：合計50人/時

入口側が遅いと、主窓口が空いていても手前の列が伸びます。出口側が遅いと、主窓口を通った客がその先で並びます。

各工程で基本タブと同じ人物・窓口表示を使う連結モデルです。到着はポアソン過程、サービス時間は指数分布。待機場所の上限・工程間の移動時間は省略しています。出口の列が主窓口をふさぐ現象は扱いません。1秒で1分進み、60分で停止します。どちらの例にも同じ時刻に客が到着します。

理論の参考：Bertsekas & Gallager, Data Networks — Queueing Theory。本文と計算例はオフラインでも利用できます。
