# 待ち行列シミュレーター

窓口の待ち行列 (M/M/c) を、スライダーを動かしながらアニメーションで見るツール。

**`index.html` をダブルクリックするだけで動きます。** インストールもサーバーも不要で、
外部ファイルも読み込みません（HTML 1枚に CSS と JavaScript が入っています）。

最初にトップメニューを表示する。タブは5つあり、トップメニューのカードからも移動できる。

| タブ | 見るもの |
| --- | --- |
| トップメニュー | 各シミュレーションとチュートリアルへの入口 |
| チュートリアル | 待ち行列理論、利用率ρ、待ち時間の急増、一時的な過負荷、目標利用率、前後のボトルネック |
| 基本（定常状態） | 到着数・サービス速度・窓口数・到着のバラツキを変えて、定常状態での行列を見る |
| 開店日シミュレーション | 12:00 一斉オープンの1日。開店前の行列と先行受付、時間帯ごとの到着数と窓口数 |
| 行列ボトルネック | スマホ歩行・立ち止まり・通路の狭窄による滞留と流出の変化 |

# タブ1: 基本（定常状態）

## 操作するもの

| スライダー | 範囲 | そこから決まる値 |
| --- | --- | --- |
| 1時間あたりの到着数 λ | 0–240 人/時 | 平均到着間隔 = 60/λ 分 |
| 到着のバラツキ Ca | 0–3 | 到着間隔の変動係数 |
| 1窓口1時間あたりのサービス数 μ | 1–240 人/時 | 平均サービス時間 = 60/μ 分 |
| 窓口数 c | 1–12 | 処理能力 = cμ 人/時 |
| 再生速度 | 0.25–20 | 実時間1秒で進むシミュレーション分 |

サービス時間は指数分布。到着間隔は平均 60/λ 分を保ったまま、バラツキだけを変えられる。

## 到着のバラツキ

到着間隔は形状 1/Ca²・尺度 (60/λ)·Ca² のガンマ分布から引く。平均と変動係数が
ちょうど Ca になり、スライダー1本で次の3つが連続につながる。

| Ca | 到着のしかた |
| --- | --- |
| 0 | 一定間隔。きっちり 60/λ 分おきに1人 |
| 1 | 指数分布 = ポアソン到着。完全にランダム |
| 2–3 | 長い空白のあと、数人がかたまって来る（バースト） |

**到着数が同じでも、バラツキが大きいほど待ち時間は伸びる。** これが待ち行列理論の
勘どころで、λ=45人/時・μ=60人/時・1窓口（ρ=0.75）で15万分回すと実測はこうなる。

| Ca | 実測の平均待ち時間 |
| --- | --- |
| 0（一定間隔） | 1.21 分 |
| 1（ポアソン） | 2.94 分 |
| 2 | 8.07 分 |
| 3（バースト） | 19.40 分 |

窓口も到着数も何ひとつ変えていないのに、待ち時間は16倍になる。

スライダーを動かしても**行列・窓口・統計・グラフはそのまま引き継ぐ**ので、
条件を変えたときに状態がどう移っていくかを途切れずに追える。
まっさらからやり直したいときは「リセット」ボタン（または R キー）。
Space キーで一時停止・再開。

## 画面の見かた

- 左から客が到着し、1本の待ち行列に並び、空いた窓口へ移動して、右へ退出する。
- Ca を上げると、しばらく誰も来ない時間のあと数人がまとまって入ってくる。
- 客の頭の上の数字が、その人の待ち時間（分）。行列が詰まっているときは間引いて表示する。
- 客の色も待ち時間を表す。青緑 → 琥珀 → 赤（平均サービス時間の3倍で赤）。
- 窓口のバーはサービスの進捗、右の数字は残り時間。
- 下のグラフは待ち人数の推移。破線は理論値 Lq。
- 指標タイルは実測値と理論値を並べて表示する。

## 理論値

左パネルの「理論値」は、スライダーの値だけから定常状態の値を計算して出している
（シミュレーションの結果ではない）。使っている式も同じ枠内に書いてある。

Ca = 1 のときは M/M/c の厳密解。Ca ≠ 1 のときは Allen–Cunneen 近似に切り替わる。

```
Wq(G/M/c) ≈ (Ca² + Cs²)/2 × Wq(M/M/c)      Cs = 1（指数サービス）
```

この補正係数も「バラツキ補正」として画面に出している。Ca=2 なら ×2.5、Ca=3 なら ×5。
近似なので Ca が大きい領域では実測より小さめに出る（Ca=3 で 2〜3割ほど）。
画面にもその旨を出している。

| 出している値 | 式 |
| --- | --- |
| 平均待ち時間 Wq | Lq / λ |
| 平均待ち人数 Lq | C(c,a) · ρ/(1−ρ) |
| 平均滞在時間 W | Wq + 1/μ |
| 平均系内人数 L | Lq + a |
| 待たされる確率 | C(c,a)（Erlang C） |
| バラツキ補正 | (Ca² + Cs²)/2 |
| 提供トラフィック a | λ/μ（アーラン） |

利用率 ρ = λ / (cμ)。ρ < 1 のときだけ行列は定常になる。

Erlang C は、Erlang B の漸化式 `B(n) = aB(n-1) / (n + aB(n-1))` を c まで回してから
`C = B / (1 − ρ(1 − B))` で求める。階乗や a^c を直接扱わないので、窓口数が多くても
桁あふれしない。

ρ ≥ 1 では理論値は ∞ になり、画面上でも行列が伸び続ける。

教科書どおりの式（P0 を直接和で求めるもの）と 9 通りのパラメータで照合して、
相対誤差 1e-9 以内で一致することを確認してある。リトルの法則 L = λW も成立する。

## 中身

`index.html` の `<script>` は3つに分かれている。

1. `Sim` クラス — M/M/c の離散事象シミュレーション。時間単位は分。
   次の事象（到着 / サービス完了）まで時計を進めては処理する、を繰り返す。
   時間加重で Lq と稼働率を積む。
2. 理論値 — `erlangC()` と `theoryOf()`。
3. 描画 — Canvas 2D。シミュレーションの状態を目標位置として、客を指数補間で滑らかに動かす。

# タブ2: 開店日シミュレーション

10:00 から窓口の前に行列ができ始め、**12:00 に全窓口が一斉オープン**、**16:00 で受付終了**。
受付終了後は到着が止まり、残った客をさばき終わるまで窓口を開け続ける。

## オープン前待ち行列と先行受付

開店前は窓口が閉じているので、来た客はそのまま並ぶ。この行列を係員が回って
**先行受付**をする。受付が済んだ客は、窓口を短い時間で通過できる。

| 設定 | 既定値 |
| --- | --- |
| 先行受付の係員数 | 3 人（0〜6） |
| 先行受付1件の時間 | 1.5 分 |
| 開店後も行列で受付を続ける | する |
| 窓口のサービス時間（受付していない客） | 4.0 分 |
| 窓口のサービス時間（先行受付済みの客） | 1.0 分 |

先行受付が済んだ客は、画面上では**緑の縁取り**がつく。窓口に入るとサービス時間が短くなり、
進捗バーも緑になる。受付の途中で窓口に呼ばれた客は、係員が手を離してそのまま窓口へ行く。

## 時間帯ごとの到着数と窓口数

画面下の帯で、1時間ごとに設定する。

| 時間帯 | 到着数（既定） | 窓口数（既定） |
| --- | --- | --- |
| 10:00 | 30 人/時 | 閉（行列のみ） |
| 11:00 | 90 人/時 | 閉（行列のみ） |
| 12:00 | 180 人/時 | 6 |
| 13:00 | 120 人/時 | 5 |
| 14:00 | 80 人/時 | 4 |
| 15:00 | 60 人/時 | 3 |

到着は区分定常のポアソン過程。単位指数分布の「残量」を時間帯をまたぎながら消化するので、
時間帯の切れ目でも到着率が正しく切り替わる（20回平均で設定値との誤差 5% 以内を確認）。

窓口数を減らす時間帯に入ると、その窓口でサービス中だった客は行列の先頭に戻る。

## 当日の結果

左下に出る。**最長の待ち時間**には、開店前から並んでいる人が開店を待つぶんが入る
（10:00 に来た人は必ず約120分待つ）ので、**「うち開店後に来た客」**の平均と分けて見る。

既定の設定（合計 560 人）で係員の人数だけを変えると、こうなる。

| 先行受付の係員 | 最大待ち | 平均待ち | 先行受付率 | 全員さばけた時刻 |
| --- | --- | --- | --- | --- |
| 0 人 | 443 分 | 231 分 | 0% | 23:25 |
| 1 人 | 119 分 | 56 分 | 49% | 17:01 |
| 3 人 | 119 分 | 16 分 | 68% | 16:02 |
| 6 人 | 119 分 | 14 分 | 69% | 16:06 |

係員なしでは窓口の処理能力（6窓口 × 15人/時 = 90人/時）が到着にまるで追いつかず、
行列が315人まで伸びて深夜までかかる。係員を3人置くだけで定時に終わる。

# タブ3: 行列ボトルネック

通路を上から見ながら、遅い人の後ろに列が伸びる様子と、狭窄部への合流を観察する。
「通常歩行」「スマホ歩行」「狭窄のみ」「両方」のボタンで条件を比較できる。

| 設定 | 範囲・動作 |
| --- | --- |
| 到着人数 | 0〜180 人/分。既定は140人/分 |
| スマホ歩行者の割合 | 0〜100%。既定は30% |
| 通常の歩行速度 | 0.6〜1.8 m/秒。既定は1.2 m/秒 |
| スマホ歩行の速度 | 0.1〜1.2 m/秒。既定は0.4 m/秒 |
| 通路・狭窄部の幅 | 1〜4列（1列0.6m）。狭窄部は通路幅以下 |
| 追い越し | 空いた隣の列へ進める。無効でも狭窄部への合流は行う |
| 再生速度 | 1〜20倍 |

青緑の丸は通常歩行者、紫はスマホ歩行者。赤い輪は前方のマスが埋まって進めない人。
通路内の人数、入口で待つ人数、通過済み人数、平均通過時間、直近1分の流出人数を表示する。
平均通過時間は入口待機を含む退出済みの人の平均なので、まだ退出していない人の待ち時間は含まれない。
グラフは通路内と入口待機を合計した滞留人数の直近5分。

再生速度以外の設定変更は計算をリセットする。リセット・プリセットは固定シードを使い、
到着用と歩行動作用の乱数を分けているため、同じ到着率なら条件間で同じ人数が到着する。
Spaceで表示中のタブを一時停止・再開、Rでリセットできる（入力・ボタン操作中を除く）。

## モデルの前提

`BottleneckSim` は長さ36m・1マス0.6mの格子を0.1秒刻みで更新する。
内部時計は既存モデルと同じく分。到着はポアソン過程で、空いている入口から入場する。
各マスは1人まで。下流から順に前方の空きマスへ移動し、合流の優先方向は交互に切り替える。
狭窄部は入口から18〜24mの6m区間。スマホ歩行者は低速で歩き、歩行中は毎刻み約1/300の確率で
1〜3秒立ち止まる。実際の移動速度は格子・更新間隔・混雑の影響も受ける。
入口待機は最大10,000人で、超過分は計算対象外として画面に明示する。

このモデルは仕組みを観察するための簡易モデルで、実測で校正した群集流・避難予測ではない。

## 開発時の検証

Node.jsの組み込みテストランナーで実行（追加パッケージ不要）：

```sh
node --test tests/bottleneck.test.cjs
```

JavaScript構文、人数保存、マスの重複、狭窄壁の通過禁止、全幅の組み合わせ、
到着停止後の排出、固定シードの再現性、条件による流出の差を検証する。
画面変更時はブラウザーで3タブ・スライダー・停止/再開・リセット・画面幅・テーマも確認する。


## トップメニューとチュートリアル

チュートリアルでは、1窓口・平均サービス時間1分の M/M/1 の理論値を、
利用率0〜110%のスライダーで確認できる。ρ < 1 では Wq = ρ/(1−ρ) 分、
ρ ≥ 1 では有限の定常平均がないことを表示する。
目標利用率70〜80%は検討の出発点としての提案であり、一律の基準ではない。
許容待ち時間・窓口数・ばらつきに応じた検証が必要であることを説明する。

トップメニュー・チュートリアル表示中は各シミュレーションの時計を進めず、
Space / R でも操作しない。シミュレーションに戻ると元の状態から再開する。
タブは左右矢印・Home・Endでも選択できる。説明本文と計算例は外部通信なしで利用可能。


### チュートリアルの操作図

- 02：λ（0〜240人/時）とμ（5〜60人/時）のスライダーでρを計算。窓口数は4で固定。
- 03：横軸ρ・縦軸平均待ち時間（分）のグラフを表示。既存のρスライダーと連動し、ρ ≥ 1では有限の定常値がないことを表示。縦軸の上限は100分。
- 04：基本タブと同じM/M/1モデル・人物と窓口の描画で過負荷を表示（到着120人/時、処理100人/時）。独立した状態と固定シードを使用。
- 05：30分の過負荷からの回復を平均流量のアニメーションで表示。
- 06：4〜12窓口を比較。到着90人/時・1窓口30人/時のM/M/c理論値と、仮の費用2,000円/窓口/時を表示。待ち時間短縮と追加費用の関係を示し、最適な窓口数は一律に決めない。
- 07：入口60人/時・窓口120人/時・出口50人/時に対して90人/時が到着する例。工程間の移動時間を省き、無制限に待てる平均流量モデルで入口・出口の蓄積を示す。

各アニメーションには停止・再生・リセット操作がある。04は1秒で1分、05・07は1秒で5分進み、60分で停止。06の稼働表示は概念図で、個々の客を追跡しない。OSの「動きを減らす」設定では初期停止する。

02は1窓口の処理能力と合計処理能力を併記。02ではc・λ・μ・合計処理能力・ρの意味と単位を一覧で説明する。03のρ ≥ 1の表示は「∞」（有限の定常値なし）。

利用率の表示色は基本タブ・チュートリアルで統一：ρ < 0.8は青緑、0.8 ≤ ρ < 1は黄色、ρ ≥ 1は赤。数値・状態の説明を併記し、03のグラフにも黄色・赤の領域を表示する。これは負荷の目安であり、待ち時間の保証ではない。07は窓口だけでなく入口・出口の過負荷も赤で示す。

02では窓口を独立した処理単位、サービス時間を対応開始から終了まで（待ち時間を除く）と定義。03では窓口減少・サービス時間延長がρを押し上げる例を掲載し、ρ ≤ 0.8でも待ち時間が生じることを説明する。
